# v0.1 冻结线：只做本地链路，其余留占位、许可搁置

v0.1 的纵向内容是 **本地漫画 → 归档直读 → 解码 → GPU 上屏 → 超分** 这条链。
在线源（QuickJS 插件）、OCR 翻译、上色、Anime4K、视频播放**全部不进 v0.1**。

> **范围扩张（2026-09-16，见 ADR-0009）**：v0.1 另加一条**横切**能力——**操作绑定体系**
> （可自定义的键位 / 鼠标 / 滚轮 / 触屏到「动作」的映射）。它不改变上面那条纵向链，
> 但确实扩大了 v0.1 的实现面。放行的理由只有两条：用户直接要求；
> 且它是判据 C（自动连续翻页 100 次并采 `FrameTiming`）的实现前提——硬编码在
> `Focus.onKeyEvent` 里的路径无法被程序化驱动，测出来的是「模拟按键 + 渲染」而不是「翻页 + 渲染」。
> 除这两条之外冻结线不变。

「推迟」不等于「不做」，而是**留占位**：

- `PageSource` 与 Reader **不得假设「一页 = 一张静态图」**（为视频页留位）—— 这个前提现在定型几乎免费；
- 页面渲染层预留一个**页后处理**位（上色与 OCR 翻译在结构上是同一类：页解码之后的图像变换），
  v0.1 不实现，也不把它固化进公开接口；
- 超分**以 mImageViewer 的 Rust 核心为准**（`ort` + Real-ESRGAN / Real-CUGAN / NMKD-Siax），
  Windows 先行、macOS 后续转原生（平台顺序见 ADR-0006）；**Anime4K 与上色不进 v0.1**。
- 操作绑定的**输入描述 schema 覆盖 9 类设备**，其中游戏手柄 / 鼠标轨迹手势 / 轮盘
  只可解析、不可编辑（ADR-0009）——schema 一旦有用户数据就难改，运行时处理器可以逐个补。

**许可搁置**：不预先决定把 Rossi 改为 GPL-3.0，因此**任何 GPL 源码不得进入本仓库**。
将来若要做 OCR 翻译 / 上色 / Anime4K，默认路线是「读 Venera-SSR 的问题定义 + 自行重写 + 使用公开模型」。
这个开关随时可以拨动，但拨动是一个独立的、需要单独决策的决定。

## Considered Options

- **把在线源放进 v0.1**：QuickJS 运行时与插件生态已经生产可用，看起来更像「拼装」而不是新功能。
  但它会把 v0.1 的验收面从「本地阅读」扩大到「网络 + 插件错误处理 + 源站变化」，
  而 v0.1 的判据只关于本地阅读。
- **OCR 翻译起步就做**：它是这个项目最有辨识度的能力，也是最贵的一项（检测 + 识别 + 翻译 + 排版回填），
  且 GPL 约束使它不能直接抄参考实现。
- **现在就决定 GPL**：换来源码自由度，但等于把整个仓库的分发条款交给一个尚未验证要不要做的功能。

## Consequences

- 「个人自用」（ADR-0006 / Q1）第一次真正开始约束范围 —— 在此之前它是一个不产生约束力的目标。
- 优先级随之确定：**「上屏拷贝按需而非每帧」优先于「零拷贝」**（Gate A-W 的结论），
  因为前者是 v0.1 链路上的实现约束，后者要付 fork `wgpu-hal` 的长期代价。
- **Rossi 在 v0.1 阶段是一个本地阅读器**，与「拼装成熟能力」的定位有一段距离：
  在线源是 Breeze 已经提供、最能体现「拼装」的部分，却排在 v0.1 之外。
- 冻结线的作用机制：**能力清单 + 可数判据**。判据已定稿于 `docs/v0.1_acceptance.md`
  （覆盖度 A / 冷启动 B / 翻页帧时间 C / 内存 D，及操作绑定 E）。
  **旧表述「v0.1 的可数判据仍未确定」已废弃**——冻结线现在同时靠清单与数字起作用。
- 范围从「纯纵向链路」变为「纵向链路 + 操作绑定横切」后，v0.1 的**最小可交付体量上升**。
  这是明知代价接受的结果：绑定体系的 schema 一旦有用户数据就难改，早做比晚做便宜。
