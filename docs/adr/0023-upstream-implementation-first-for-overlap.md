# 重叠功能优先采用上游实现

**本 ADR 收窄 ADR-0002 的适用范围，不作全面取代。** ADR-0002 的「允许破坏性重构、不承诺改动可上游化、
不向上游提 PR」继续成立；作废的是其中「`upstream` 降级为参考来源、共享代码的修复靠人工挑选」那一条：
自 2026-10-13 起，**上游（`deretame/Breeze` 与 `MikageSawatari/mimageviewer`）已经实现、且这份实现
在本仓可用的重叠功能，一律以上游代码为正本**，本仓不再保留同一功能的平行实现。

## Context

Rossi 同时有两个上游：Dart 侧功能来自 Breeze（fork 来源），`rust/local_core` 的策略模块来自
mImageViewer（ADR-0001 / ADR-0007 的 gitlink + 搬源码形态）。ADR-0002 当年定的口径是
「保留拉取能力但不为对齐付出代价」，实际执行了两轮之后暴露的代价不在合并上，而在**合并之后**：

- 同一功能存在两套实现时，每次同步都要重新判一遍「上游这版要不要换掉本地那版」，
  上一轮的决定不产生任何累积；
- 本地那份不参与上游的演化，上游修了判决分支（`page_load_scheduler` 的精确 seek 保留集合、
  等待请求取消、permit 释放后的取消标记这一类），本仓只能靠人工读上游 diff 补——
  这正是 [移植模块同步说明](../local-core-vendored-modules.md) §2.2 那张「脚本看不到的那四份」人工读表；
- 单人项目同时维护两套接口纪律，就是 ADR-0002 当初否决「双轨」的理由，而平行实现事实上把双轨养回来了。

2026-10-13 的同步（`dc3498c4`）按新口径执行过一次，规模是实测的：Breeze 跟进 21 个提交，
mImageViewer 从 v4.1.0 快进 895 个提交到 v4.6.0。

## Decision

1. **判据是功能目标，不是文件名或数据结构。** 上游有一个达成同一目标的实现，就算重叠；
   本仓那份改判为「平行实现」，下次同步（或下次因别的任务碰到该模块）时换成上游的。
2. **本仓的额外行为挂到上游实现上，不另起一份。** 落点固定为两种：薄适配层
   （只暴露本仓需要的接口形状，判决逻辑一律走上游那份）与已登记的扩展点
   （Rust 侧进 `script/sync_vendored_modules.py` 的 `PORTS`，Dart 侧进 [上游同步记录](../upstream-sync.md)）。
   本轮的实例：阅读设置组件、单本稀疏覆盖与 v12 迁移、章节分组、插件详情、图形验证码、
   自定义登录标签、Freezed 状态、下载持续重试全部采用上游；QuickJS 原生二进制通道**删掉了 JSON 兜底**；
   下载队列只保留本仓的限流识别，操作内重试循环改用上游。
3. **「上游有同名文件」不等于重叠。** 上游那份在本仓不可用时不属本规则，仍保留本地实现并登记，
   三条先例见下表。
4. **优先上游不构成缩能力的许可。** 换成上游实现后，本仓独有的行为必须有回归测试兜住，
   差异必须登记；漏登记会被同步脚本误报成「上游改了」，也会让下一个人把有意偏离改回去。

| 情形 | 上游 | 本仓 | 为什么不判成重叠 |
|---|---|---|---|
| `folder_tree` 导航层（上游 `c633825c`） | `NavigationArchivePolicy` + 落点解析 + 每请求决策 memo | 单窗，上下本走 `book_navigation.rs` | `resolve_folder_nav_landing` 的 `DetachedReadable` 分支直接查 `ArchiveCacheDb::peek()`，而转换缓存是本仓没有的 G-02；DFS 导航族在本仓**没有生产消费者**，搬来即死代码（§8.1） |
| 文件夹代表图「直下图片优先」（上游 `9a905104`） | 一个文件夹 = 一张代表图 | `thumbnail_pipeline.rs:199` 向 `resolve_folder_thumb_images(…, 4, …)` 要最多四个子项**合成**封面 | 换成直下优先后，既有子目录又有一叠连续页的文件夹会被同一章前四页占满，正好抹掉合成封面（§8.2） |
| `file_ops` 三份（`selection` / `execute` / `clipboard`） | `delete_worker.rs` / `cut_clipboard.rs` / `shell_file_ops.rs` | T4 平台等效重写 | 上游三份函数体内分别是 21 / 11 / 14 处 Windows API，**一行都编不过**；写进 `PORTS` 只会产出一份无意义的 diff（§2.1） |

## Considered Options

- **维持 ADR-0002（上游只作参考、人工挑修复）**：自由度最大，但两套同功能实现各自演化，
  每次同步都要重判一遍，且本地那份吃不到上游的判决修正。本次要终结的正是这项。
- **无条件对齐上游**：把上表三条也换成上游形态。代价是得到一段没有消费者的导航层死代码、
  一套被抹平的封面合成策略，以及一份在 macOS / Linux 上根本编不过的文件操作。
- **本 ADR（重叠取上游，不可用与独有留本地并登记）**：代价是本仓要持续维护「什么算重叠」的判据
  和登记台账——比维护两套实现便宜，比无条件对齐诚实。

## Consequences

- **本规则只对未来生效，不发起全仓追溯排查**（用户 2026-10-13 定）。已有的平行实现在
  下次同步或下次因别的任务碰到该模块时顺带收敛；不专门开一轮清理。
- **ADR-0002 已加修订注记并指向本 ADR**；`CONTEXT.md` 的「上游同步」词条同步改掉——
  原措辞是「**不对齐**它们」，与本规则字面冲突，现在的口径是「重叠功能以上游实现为正本，
  Rossi 独有功能与跨平台差异保留在薄适配层并登记」。
- **AGENTS.md 新增 §13「上游优先」**，与 §6.6「只提交本功能文件」并列成为改代码时的口径；
  任何 agent 在动 `lib/` 或 `rust/local_core` 前先读它。
- **登记台账变成硬要求**：Rust 侧不写进 `PORTS` 的偏离会被 `sync_vendored_modules.py` 的自检
  报成未登记偏离（脚本第 2 步），Dart 侧没写进 `docs/upstream-sync.md` 的差异则在下次同步被重判一遍。
- **保留一条失明区**：上表三条既然不进 `PORTS`，上游改动它们时脚本**不会**报警，
  仍要人工读——这与「优先用上游」不矛盾，正是这条规则要求人工判断的那部分。
- 口径的边界不在本 ADR：具体采用了哪些上游实现、验证到什么程度，见
  [上游同步记录](../upstream-sync.md) 与 [移植模块同步说明](../local-core-vendored-modules.md)。
