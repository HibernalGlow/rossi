## 为什么要动：缺的不是几个按钮，是一个一直没有的结构性落点

现在的渲染链上，「页解码之后、上屏之前」只能挂**一个**替代位图生产者：超分与 OCR 成品页
各占一位，且互斥（ADR-0018 的口径是「换画面走呈现器增强图轨（与超分互斥）」）。
这个形状是 ADR-0008 当初留的「页后处理位」，它按「上色与 OCR 在结构上是同一类：
页解码之后的图像变换」定型，**定型时假设了「一次只有一档」**。

上面这批能力全部要求打破那一条假设，且不是各自能绕开的：

- **降噪与超分是两段**（1× 与 2×/4×），「先降噪再超分」意味着一个页在同一条链上被处理两次；
- **滤镜预设**要求亮度/对比度/伽马/色温/饱和度/锐化能组合、能按书覆盖；
- **局部调整层**要求「同一页 + 一串带遮罩的调整描述」可重复合成 —— 这正是 ADR-0008
  那句「不引入『一页 = 图层集合』」字面上禁止的形状。

所以本 ADR 不是「加功能」，是**把那个单位改成一条可组合的链**，并顺带把 ADR-0018
已经做过一次的那句冻结线收窄再推进一步。不加这层，上面六项只能各写一套上屏路径，
而仓库的口径是同一功能不许有平行实现（ADR-0023）。

## 决定

### 1. 处理链的形状：一条有序的阶段列表，产出仍是「替代位图 + 派生指纹」

`解码 → 非破坏式处理链 → 上屏`，链由若干阶段按固定顺序组成，**每个阶段的输出是下一个阶段的输入**，
链的末端才是那份「替代位图」。`PageSource` 的公开形状**不变**（ADR-0018 收窄后的口径继续成立：
那句冻结线只约束 `PageSource` 的公开形状）。

顺序是**语义的一部分**，不是实现细节：降噪→超分与超分→降噪的产物不同，网点保留程度也不同。
因此链的形状必须显式建模成一个有序序列，而不是几个布尔开关。

### 2. 派生身份必须含链本身

缓存与内存索引的键必须覆盖：**每一档的模型标识 + 该档的参数指纹 + 档序**。
只按「模型 id + 倍率」键的话，打开降噪或调滤镜会命中上一份未处理的产物 ——
「开了开关却显示旧结果」是这条链唯一真正会被用户感知到的失效模式。

判据（必须能在验收里跑）：改一个滤镜参数 ⇒ 该页产物档名变；把降噪挪到超分前后各一次 ⇒ 两档不同名；
参数改回原值 ⇒ 命中回旧档（不许累积孤儿档）。

### 3. 上游优先：算法以 mImageViewer 那份为正本（ADR-0023）

- **局部调整层**：复用 `crates/local-adjust-core`，**不另写一份图层合成核心**。
  落点二选一由接入实测决定：作为 path 依赖（与 `crates/unrar-patched` 同一先例，ADR-0011 第 6 条），
  或按 `rust/local_core` 现有 `include!(concat!(env!("OUT_DIR"), …))` 机制取直接源码切片。
  无论哪种，都**保留上游的名字**（类型名 / 函数名 / 常量名 / 测试名，除 `pub(crate)` → `pub`），
  并把 RossI 侧的刻意偏离登记进 `script/sync_vendored_modules.py` 的 `PORTS`
  与 `docs/mimageviewer-reuse-inventory.json`。
- **滤镜算法**：以 `src/post_filter.rs` 为参考实现逐条对照，**只取清单里那 11 项**，
  不移植 38 种滤镜的整套枚举与 UI。
- **降噪**：参考 `src/ai/denoise.rs` 的**分块推理与拼回策略**；推理后端仍走本仓既有矩阵
  （CoreML / ncnn·waifu2x CLI / `ort`），**不搬**上游的 TensorRT / DirectML worker pool
  （gap-audit §6 那条排除继续有效）。
- 许可：MIT，每个搬入文件头保留版权与来源声明；**AI 权重一律首下、不随包**（ADR-0018 §决定 5）。

### 4. 滤镜集合（第一梯队 4 的具体范围）

基础调整：亮度、对比度、伽马、色温、饱和度。
色调预设：灰度、反色、暖色、护眼。
细节：可调强度的锐化、黑白漫画对比度增强。

不做：CRT / 复古调色板 / 胶片风格 / 色彩分级 LUT 那类「风格化」滤镜 —— 它们是图库展示语境，
不是阅读语境，且要拖进 LUT 资源管理。想加时另开决策，不在本 ADR 的放行范围内。

### 5. 预设作用域：全局默认 + 单本覆盖，两级

与「本书超分」同一套解析入口（同一形状、同一处判定），**不再开第三条按书覆盖的通道**。
局部调整层的存储作用域是**页**（遮罩天然按页画），它挂在那份「可重复合成的描述」上，
不进全局预设。

作用域解析必须有一个唯一入口，且**在渲染路径上**：设置页只是它的编辑器。
「全局开了滤镜、某本书显式关掉、这一页又叠了一层」三种状态要能各自回读到当前生效值，
不允许 Dart 侧重算一遍、Rust 侧再算一遍（那是平行的两份判定）。

### 6. 降噪的四种模式与不许静默回退

用户可选：**原图 / 仅降噪 / 仅超分 / 降噪→超分**。
链上任何一档选定了加速后端（GPU / ANE / CoreML）后**不许静默退回 CPU**：
退不退由用户决定，且界面必须看得见实际用了哪条后端。
允许回退的那一档必须「有界 + 可见」——每页无界重试会让一章撞墙上百次，判据用请求/字节数而不是时间。

### 7. 图像分析模式落「开发者工具 / 高级设置」，不进普通读者路径

取色器、直方图、灰度查看、局部颜色差异分析。它的用途是**给这条链当尺**：
调去白边阈值、判断降噪有没有抹掉网点、锐化有没有光晕。
因此它的读数必须来自链上真实的那份像素，而不是另开一次解码 —— 否则分析的是 A、画面是 B。

### 8. 放大镜与对比：扩现有那一个，不新建第二条渲染轨

对比形态是「原图 vs 处理后」：分割线拖动 + 按住临时切回原图。
实现要求是**同一份纹理的两个来源在同一层里切换**，不允许为了对比再引一条独立的解码/上屏通路
（那会立刻和 §2 的派生身份打架）。
「按住切回原图」那个动作要能进操作绑定引擎，和轮盘 / 键位 / 触屏走同一条注册路径。

### 9. 信息面板只披露回读得到的事实

尺寸、格式、压缩类型、文件大小、当前页实际经过了哪几档处理（含降噪/超分/滤镜是否命中缓存产物）。
**来源没说的就不显示**，空值不许回退成「面板自己猜的一个词」。
AI 生成元数据（PNG prompt / EXIF）那条继续不做 —— gap-audit §6 那条排除没有被推翻。

## 明确不做（以及重新放行的条件）

| 不做的项 | 理由 | 若要放行 |
|---|---|---|
| **手动选区擦除与 AI 修复**（清单 3） | 要再接一个修复模型 + 遮罩编辑 + 结果合成 + 恢复四件事；本仓 OCR 那条链已经有 LaMa 擦字与「擦字底图」落盘，同一功能不许有两套基础设施（ADR-0023）。当前口径是**先用现有 LaMa 能力评估**，不新接模型 | 先证明现有 LaMa 管线能在阅读语境复用，再单开一条 ADR |
| **非破坏式旋转 / 手动裁切 / 结果导出**（清单 5） | 「导出」是对用户归档做写操作，与本仓「不写回 CBZ/ZIP 原始页」的现状一致且需要独立的写入安全模型；旋转/裁切是显示几何变换，与像素后处理链是**正交的两件事** | 导出属另一类能力（要配事务与崩溃恢复，参照 gap-audit G-03 那一档），另行立项 |
| **图像处理的撤销 / 重做**（清单 8） | 用户明确「八不用做」。**代价写清楚**：局部调整层没有 undo/redo，误刷一块区域的恢复手段只有「删那一层」和「整页重置」两档 | 用户重新点名时，与清单 2/3 一起规划（原清单作者的意见也是「不要等编辑功能写完再补」） |
| **自动去白边** | 裁决时已在另一条讨论里，不属本 ADR | 与本 ADR 共用 §1 那条链的落点与 §2 的派生身份，届时不需要新形状 |
| 38 种滤镜全量 / 风格化滤镜（CRT、胶片、LUT、色彩分级） | 图库展示语境，不是阅读语境；且拖进 LUT 资源管理 | 点名要哪种风格时再评估 |
| 上游 `src/ai/` 的 TensorRT / DirectML worker pool | NVIDIA/Windows 专有，与本仓五平台矩阵冲突（gap-audit §6 继续有效） | —— |

## Considered Options

- **保持「一次只有一档替代位图」，把滤镜/降噪/局部调整都塞进超分那一个枚举**：改动最小，
  但「降噪→超分」这种顺序无法表达，且参数指纹会挤在一个 model id 里。这正是本 ADR 要解除的那个假设。
- **在 Flutter/Dart 侧用 shader 或 `ColorFiltered` 做滤镜**：看起来最省事，且不动 Rust。
  被否决的理由是硬的 —— Dart 侧拿不到那份未处理像素的**唯一真源**（像素不过桥是 Phase 1 的结论），
  做出来必然是「分析的是 Rust 那份、画面是 Dart 那份」两套；而且放大镜对比与直方图都会跟着裂开。
- **把整个 mImageViewer 当编辑器搬进来**：上游是单体 egui 应用（`src/app.rs` 七万六千行），
  且 ROADMAP「明确不做」里有一条「不把 mImageViewer 的显示管线照抄进来」。否决。
- **自己写一份图层合成核心**：比搬上游更快起步，但同功能两套实现是 ADR-0023 明确禁止的那件事，
  而这次上游那份恰好是**独立 crate 且零 UI 耦合**（本轮实测），没有理由不拿。

## 后果

1. **ADR-0008 需要就地改写**那一条「页面渲染层预留一个页后处理位」：那一句按「一次一档」定型，
   现在要改成「一条有序阶段链 + 派生指纹含链本身」。
2. **`docs/mimageviewer-gap-audit.md` 的排除行要改**：G-24「编辑与标注全家桶 —— 明确排除」被
   **部分推翻**（其中的局部调整层与滤镜已采纳；擦除/克隆/上色/裁切导出仍排除）。
   G-05（滤镜链）与 G-21（显示后处理）按 §4 与 §1 改写状态。
3. **`docs/phase0-vendor-spike.md` §1.3 那行假阳性要更正**，否则下一个人会照着
   「local-adjust-core 碰 egui」这个结论绕开它。
4. **验收面扩大**：这条链的失效模式是静默的（旧产物、错档、后端悄悄回退），
   所以每条守卫都要配一条证伪测试，不能只断言「没报错」。
5. 移动端（Android / iOS）仍受「最低适配、零新增功能、不参与验收」约束（ADR-0006）：
   链的**结构**要在移动端编译得过，降噪在 Android 能否用现有 waifu2x CLI 链路是另一笔实测。
