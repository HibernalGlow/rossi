# 泳道聚焦「移过去卡一下」修复的实机验收清单（2026-10-03）

本轮改的是**聚焦落地那一刻的代价**与**驻留的触发时机**，代码层已经用判据钉住
（见 `docs/adr/0014-workspace-interaction-behaviors.md` 末尾那一节）。但「卡一下」是
手感，只有你真跑起来才算数 —— 下面每一条都请回报**条目号**，红的那条附上控制台输出。

跑法（macOS，仓库根目录）：

```bash
flutter run -d macos
```

设置入口：**设置 → 布局 → 泳道焦点与独占**。本轮那颗「Reader 悬停聚焦延时」的
**含义变了**：它现在只算「停住之后再看多久」，出厂 150ms；「停住」本身由内部
60ms 的静置窗口判定，没有给你旋钮。

---

## A. 手感：移过去还卡不卡

- [ ] **S1 主症状**：开一本漫画，Reader 处于**独占**（栏头按过「独占该栏」）。
      把鼠标从 Reader 横移到左泳道里**并停住** ⇒ 期望：约 0.2s 内聚焦到左泳道，
      **中间不出现「画面糊一下 / 那一页缩一下再回来」**。
      这条就是原来那个症状。红法：仍然能看见 Reader 的画面被重新排一次。
- [ ] **S2 预备态**：同样一次移动，但盯住左泳道的**边框** ⇒ 期望：指针一停，
      边框先**淡淡亮起**（约 0.06s 后），随后交互才交出去。
      路过时（一直挪着鼠标）**不该有任何闪烁**。
- [ ] **S3 路过不误触**：鼠标从 Reader 一路横穿左、右泳道走到窗口边缘，中途不停
      ⇒ 期望：一路上谁都不被激活，也不亮边框。
- [ ] **S4 反向回 Reader**：从左泳道把鼠标停回 Reader 上 ⇒ 同样约 0.2s 聚焦回 Reader，
      且 Reader 的画面**不重新解码**（不闪、不糊）。

## B. 新的宽度口径（这条是行为变化，请确认是你想要的）

- [ ] **W1 Reader 不再塌陷**：Reader 独占且激活时，把交互交给左泳道 ⇒
      期望：**Reader 的宽度一字不变**，只是条带往左平移，把左泳道移进来；
      Reader 在视口里剩多少看多少（`readerPeekWidth` 那条缝仍然保证点得回去）。
      旧行为是 Reader 当场缩回常规宽度。若你更想要旧呈现，说明一下，这条是唯一
      需要回退的东西（其余修复都不依赖它）。
- [ ] **W2 点那条缝回独占**：W1 之后点 Reader 露出来的那一部分 ⇒ 期望：立刻回到
      Reader 占满，**没有等待、没有重解码**。
- [ ] **W3 面板独占保持原样**：在**左**泳道按「独占该栏」，然后把交互交给右泳道 ⇒
      期望：左泳道**照旧缩回常规宽度**（这一档本轮刻意没动，理由写在 ADR-0014）。

## C. 切换栏那一档（开着「Reader 独占时显示泳道切换栏」时）

- [ ] **R1 点轨之后轨会展开**：打开那颗开关，Reader 独占，点左轨 ⇒ 期望：左泳道
      从 44px **展开成自己的宽度**（旧版偶发「点完轨仍是 44px，里面点不动」）。
- [ ] **R2 回到 Reader 后轨又回来**：点 Reader 的窄缝回去 ⇒ 期望：左右两条又收成轨。

## D. 触屏（如果有手机/平板在手边）

- [ ] **T1 没退步**：Reader 独占时左右两条仍是把手，点它们仍能交出交互
      （本轮把「激活那条不收成轨」写进了几何，触屏这条路径靠的就是它）。

## E. 回归：这些不该变

- [ ] **G1 第一下点击仍被吞**：在**非激活**泳道的内容上点第一下 ⇒ 仍然只激活、
      不派发（这轮考虑过放行，实测口径决定**不做**，理由见 ADR）。
- [ ] **G2 栏头按钮第一下就生效**：非激活泳道栏头上的折叠/独占按钮 ⇒ 第一下就动。
- [ ] **G3 边缘揭示**：Reader 独占时贴住视口左边缘**停住** ⇒ 左泳道被揭示并接管；
      一路扫过边缘不停 ⇒ 不该被呼出来。
- [ ] **G4 Reader 全屏翻页**：全屏时横向拖动不拽走条带（那颗闸没被这轮碰过）。
- [ ] **G5 重启后布局还在**：改过宽度/折叠过某条泳道后重启 ⇒ 布局不变
      （本轮只加了一条「激活不改宽度」，没动持久化口径）。
