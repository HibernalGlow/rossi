# 泳道悬停自动聚焦 / 呼出后自动聚焦的实机验收清单

对应改动：`WorkspaceInteractionSettings.panelHoverFocusEnabled`（新，默认**开**）
与 `revealFocusesLane`（新，默认**开**），落在
`lib/workspace/widgets/swimlane/swimlane_workspace.dart` 的两处闸口
（`_handleLaneHoverEnter` / `_pollDwells`）。口径与代价见
`docs/adr/0014-workspace-interaction-behaviors.md` 的「后续修订（2026-09-21）」。

设置入口：**设置 → 布局 → 泳道焦点与独占**（四颗延迟/开关都在这一张卡里）。

## A. 悬停自动聚焦（新扩到面板泳道）

- [ ] **H1 左栏驻留即聚焦**：指针从阅读器泳道横移到左泳道里、停住不动 ⇒ 约 0.42s 后
      左泳道成为激活泳道（栏头边框高亮、里面的卡片第一下点击不再被吃掉）。
      失败长这样：一直不跳（驻留没接上），或**一移进去就跳**（延时没生效）。
- [ ] **H2 Reader 那侧没被改坏**：同样在阅读器泳道上停 0.42s ⇒ 激活 Reader（这一条是老能力回归）。
- [ ] **H3 换目标重新计时**：在左泳道停到快触发（约 0.3s）时把指针挪到右泳道 ⇒
      右泳道要**再等满** 0.42s 才激活，不是「一进去就跳」。
- [ ] **H4 紧凑轨是豁免的**：把左泳道折叠成 44px 的轨（或开「Reader 独占时显示泳道切换栏」
      让左右都收成轨），指针停在轨上 1s ⇒ **不**激活；**点**它仍然展开/交出交互。
      失败长这样：读数时鼠标扫过边缘轨，焦点自己跑掉了。
- [ ] **H5 开关往返**：关掉「面板泳道悬停聚焦」⇒ 面板怎么停都不跳，而 Reader 那颗
      不受影响（这一对是独立开关）；再打开 ⇒ 回到 H1。关掉之后重启一次，确认还是关的。

## B. 呼出泳道后自动聚焦（新，默认开）

- [ ] **H6 贴边即接管**：Reader 独占且激活（点栏头「独占该栏」），指针贴住视口**左边缘**
      约 0.32s ⇒ 左泳道被推出来**并且**成为激活泳道，不必再点一下。
- [ ] **H7 回 Reader 的缝还在**：H6 之后 Reader 应当仍然露出**一条窄缝**（默认 56px）；
      点那条缝 ⇒ 回到独占。失败长这样：Reader 整条被挤出视口，只能靠右边缘再呼出来。
- [ ] **H8 不再自己跑回去**：H6 之后指针原地不动、或挪去左泳道里干别的事，等 1s 以上 ⇒
      条带**留在**左泳道，不会延时收回 Reader。
      失败长这样：正看着左栏，画面自己滑回 Reader。
- [ ] **H9 关掉就是原来的瞬态揭示**：关掉「呼出泳道后自动聚焦」⇒ 贴边只是「看清楚」
      （激活仍是 Reader），把指针从被揭示的泳道移开后约 0.6s 条带自动收回 Reader。
      开/关各往返一次，别只验默认那一头。

## C. 记账与观感

- [ ] **H10 老快照升级**：用上一版存过布局（拖过宽度、折叠过某条泳道）⇒ 换到这一版
      启动，**布局一项没丢**，而这两项新行为按默认**生效**（这是刻意的，见 ADR 后续修订第 3 条）。
      若不想要，用 H5 / H9 那两颗关掉。
- [ ] **H11 中英文案**：切到英文再看这张卡，四行标题/副标题都翻到位、不撑破行。
- [ ] **H12（可选）云同步**：A 机把两颗都关掉 ⇒ B 机拉下来之后也是关的；反向再验一次。

## 明确不做的

- **不给面板另起一套延时**：两处的差别是「吃不吃」而不是「多久」，第四个延时旋钮只会更难对表。
- **不让紧凑轨吃悬停聚焦**（H4）：轨只有 44px，读数时扫过去是常事。
- **不给「呼出后自动聚焦」再加一段独立延时**：揭示本身已经有 `edgeRevealDelayMs`，
  接管就发生在那一刻；再叠一段会变成「先看清楚再跳」，与这颗开关要的手感相反。
- **不加回「自动聚焦之后仍然延时收回 Reader」**：H8 的「不跑回去」是这一改动的直接推论，
  不是漏做。真想要「看一眼就回来」，把 B 那颗开关关掉（H9）。
