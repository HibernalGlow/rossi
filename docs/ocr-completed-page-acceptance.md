# 漫画翻译（成品页）验收清单

配套 ADR-0018（为什么是成品页、为什么权重首下、为什么 Android / iOS 不做）
与 `docs/REFERENCE_RESEARCH.md` §8.6（每个决定背后的实测数字）。
本文只写**在真机上怎么判定这条功能对不对**，逐条给预期与判据。

- `cargo test -p rossi_ocr_core` **21 条全过**；
- `flutter build macos --debug` 出包成功；

  `mokuro_001a.jpg` 出 15 块成品页，尺寸 827×1170、每块内都有墨、第二次构建命中缓存。
  只有翻译那一跳是假的，所以下面第 3、4、9 条仍然要真端点。

## 0. 起环境与前置

```bash
# 这台机器 Xcode 装着但 xcode-select 指向 CLT。不带 DEVELOPER_DIR 的 pub get
# 会把 macOS 的 SPM 接线写成 false，下一次构建就炸在「Unable to resolve module dependency」。
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
flutter pub get
task dev            # = cargo build windcore + flutter run -d macos
```

需要一个能用的 OpenAI-compatible 端点，二选一：

```bash
ollama serve && ollama run qwen2.5:14b        # 本机：base URL = http://127.0.0.1:11434/v1
# 或云端：base URL = https://api.deepseek.com/v1 + 对应 key
```

样本用 Manga109 的页（或任意本地已下载的日漫章节）。**必须是本地来源** ——
在线图源没有呈现器，芯片不出现（这是设计，不是 bug，见第 12 条）。

## 1. 设置页保存与回填

**做**：设置 → 漫画翻译（成品页）→ 依次填接口地址、模型名、（可选）API Key、目标语言、术语表。
**预期**：每项保存后重进页面，值原样回填；接口地址尾部多写的 `/` 不显示（存的时候已削掉）。
**判据**：列表行显示的是**存进去的原值**，不是占位文案。API Key 那行只显示 `••••••`，
任何地方都不出现明文。

## 2. 权重下载：进度、中断、半截文件

**做**：点「下载权重」（共 5 个文件约 660 MB），下到一半直接退出 App，再进来重新点。
**预期**：进度条按**总量**走（不是单文件），完成后显示「权重已就绪（5 个文件）」；
中断后重下不报「文件已存在」，也不出现「存在但不可用」。
**判据**：`getFilePath()/manga_ocr/` 里**没有** `.download_*` 残留；
`OcrModels` 的体积下限挡得住「HTML 错误页被存成模型」—— 故意把 URL 换成一个会返回登录页的
地址时，状态仍显示缺失而不是就绪。

## 3. 顶栏芯片出现与不出现

**做**：分别打开①本地已下载章节 ②插件在线图源 ③（若有）Android / iOS。
**预期**：①有「译」芯片；②没有；③设置页里连「漫画翻译」这一栏都没有。
**判据**：③是**整条入口不画**，不是点进去报错。

## 4. 按「译」：状态机与耗时

**做**：本地页面上按芯片。
**预期**：状态依次 `生成中 → 译文页`，空机上单页约 10 s（满载机器会到分钟级，别拿那个数判回归）；
期间芯片显示「生成中」，再点提示「这一页正在生成译文，稍等」。
**判据**：状态字与画面**一致** —— 显示「译文页」时屏幕上必须已经是回填后的那张；
如果注入被拒或画面没换，芯片显示「译文失败」并给出原因，**不许静默回到原图**。

## 5. 成品页质量（唯一必须靠眼睛的一条）

**判据逐条看**：
- 每只被处理的气泡里有译文，且**译文在自己的气泡内**，不越到邻泡或画面区；
- 窄高气泡是**单字一列**（ADR-0018 §3.4 第 4 条），不是 3–4 字一行的假竖排；
- 字号是自动降下来求得的，允许小，但不允许截断到读不出（截断的块应显示「可疑」标记）；
- 擦字干净：原文不残留（网点、速度线上的粗笔画残留属已知缺口，见 §8.6.2）；
- **拟声词原样保留**（「だんだんだん」那类）—— 这是设计如此，检测件不覆盖（未决 6）。

## 6. 再按一次回原图

**做**：在显示译文的状态下再按芯片。
**预期**：回到原图，芯片回到「译」。
**判据**：回原图后**超分该回来的要回来**（见第 9 条），不能出现「既没译文也没超分」的空档。

## 7. 每页独立

**做**：把第 5 页翻成译文，翻到第 6 页，再翻回第 5 页。
**预期**：第 6 页芯片显示「译」（未处理），第 5 页仍是「译文页」。
**判据**：不存在「一开全局每页都变慢」的行为。

## 8. 翻回来秒开（缓存）

**做**：第 5 页生成完成后翻走再翻回。
**预期**：不再出现「生成中」，直接是译文页。
**判据**：`manga_translated/<语言>_<模型>_<哈希>/p4.png` 只有一张，没有重复生成；
同目录 `manifest.json` 里的指纹含目标语言、端点 host、模型名、术语表哈希、权重版本标签、字体版本。

## 9. 与 AI 超分互斥（增强图轨只有一份）

**做**：开超分 → 按「译」→ 再关「译」。
**预期**：开着译文时这一页显示译文（超分让路）；关掉译文后这一页回到原图并重新超分。
**判据**：日志（超分那份 SuperResolutionLog）出现「译文页占用增强图轨，超分让路」；
**不能**出现「译文被超分图覆盖掉」的闪回。

## 10. 换目标语言 / 改术语表必须重译

**做**：同一页先出中文版，再把目标语言改成 en，重看这一页。
**预期**：显示「生成中」并产出新页，不是端旧缓存。
**判据**：`manga_translated/` 下多出**另一个**语言标签目录；旧目录不被覆盖。术语表改一个字同理。

## 11. 没配端点 / 权重没下全

**做**：清空设置里的端点（或删掉 `manga_ocr/` 里的识别件）后按「译」。
**预期**：芯片进入「译文失败」，文案分别是「还没配好翻译端点，去设置里填」和
「权重没下全：缺 <文件名>」。
**判据**：**不弹 Rust/ONNX 的原始错误**给用户。

## 12. 失败不谎报

**做**：把端点指向一个不存在的端口（或翻译中途断网）后按「译」。
**预期**：「译文失败」+ 原因（含 HTTP 状态码）。
**判据**：条数对不上时（模型漏译）报「译文条数对不上：期望 N，拿到 M」，
**不许**出现某个气泡空白而状态却显示成功。

## 13. 清空成品页缓存

**做**：设置页 → 成品页缓存 → 删除。
**预期**：显示「已生成 N 张成品页」→ 操作后显示「还没有生成过成品页」。
**判据**：**原图一张都不动**（只删 `manga_translated/`）。

## 14. Windows（可选，有机器再验）

**做**：Windows 上把推理后端选 DirectML。
**预期**：能出成品页；EP 注册失败时**明确报错**，不静默退回 CPU。
**判据**：后端选项里选的值与实际跑的 EP 一致（这条纪律来自超分：选了 GPU 就不许偷偷用 CPU）。

---

## 明确不做（别按这些来验）

- **上色 / 去字后重绘**：ADR-0018 一期只占位。
- **真竖排**：标点旋转与列读序没做；现在只有窄高框的「一字一行」。
- **拟声词检测与翻译**：检测件不覆盖，需自标数据（ADR-0018 未决 6）。
- **Android / iOS**：排除项，不是待办。
- **整本批量翻译**：一期只有逐页。
