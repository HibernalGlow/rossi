# 顶栏缩放 / 旋转（neo N-11）实机验收判据

> 范围与**刻意不做**的清单在 [feature-migration-spec.md](feature-migration-spec.md) 的 N-10 / N-11 / N-12 三行，
> 以及提交信息里；本文件**不重复写范围**，只回答一件事 —— **怎么判定一条真的通了**。
> 判据的作用与 [file-manager-acceptance.md](file-manager-acceptance.md) 相同：砍掉「看起来做了」的机会。

冻结信息：2026-09-20，对着**工作区**跑（这棵树同时有别的会话在未提交的改动里）。

**报告格式**：不通过时给 **条目号 + 控制台片段**，不要给描述。
症状到方法的映射必须是一对一的，否则修的人得先猜。

## 0. 入库红线：这三件事不算完成

1. **构建通过 ≠ 观感对。** 本轮改动全在渲染层，`flutter analyze` 与编译都证明不了任何一条视觉结论。
2. **面板画出来了 ≠ 它改的东西生效。** 每一档都要看到**画面**跟着变，不是看到按钮亮了。
3. **默认档变了观感 = 直接不通过。** 本轮唯一被允许改变默认观感的入口是顶栏面板本身。

## 1. R1 — 阅读位置（最高风险，先跑这组）

呈现层与配对是两件事：换缩放/旋转/宽页策略只该换「怎么铺」，不该换「看的是哪张」。
本仓已有明文纪律（`_syncPairingLayoutChange` 与 `remapReadModeSlotIndexForPairingChange`），
本轮把渲染层整个重写了一遍，所以这条纪律要重新验一遍而不是假定还在。

观察点：停在第 10 页附近，然后逐条操作，每次操作后**读左下角页号**。

| # | 通过判据 |
|---|---|
| 1.1 | 切 7 种缩放模式中的任何一种 → 页号不变 |
| 1.2 | 拖手动缩放滑条并松手 → 页号不变 |
| 1.3 | 顺时针 / 逆时针旋转 → 页号不变 |
| 1.4 | 切宽页策略三档 → 页号不变 |
| 1.5 | 「重置视图」→ 页号不变 |
| 1.6 | 自动旋转四组（关闭 / 纵向页 / 横屏 / 强制）逐个点 → 页号不变 |
| 1.7 | 单页 ⇄ 双页 → 停在**同一张图**（既有回归项，确认没被本轮改坏） |
| 1.8 | 「首页独立显示」来回切 → 停在**同一张图** |
| 1.9 | 「自动分割横向页」来回切 → 停在**同一张图** |

## 3. R3 — 溢出必须被裁掉，而不是被报警

上一版的缺陷：裁切用了 `UnconstrainedBox`，它带溢出指示 mixin，于是「帧比视口高」被画成
「BOTTOM OVERFLOWED BY 78 PIXELS」的条纹。现在换成 `OverflowBox` + `ClipRect`。

| # | 通过判据 |
|---|---|
| 3.1 | 适应宽度 + 一张超高竖页：纵向超出部分**被裁掉**，无条纹，图不缩小 |
| 3.2 | 手动缩放到 800%：无条纹；此时双指平移 / 双击放大仍能把裁掉的部分拖出来看 |
| 3.3 | 原始大小：无条纹（图比屏幕大时按视口裁） |
| 3.4 | 双页 + 高度对齐 + 放大：无条纹 |
| 3.5 | 旋转 90° 的横页：无条纹，且左右两侧是对称裁切而不是单边 |
| 3.6 | 上面任何一条做完后**收起顶栏**：阅读区不残留任何条纹 |
| 3.7 | 溢出状态下**点击 / 双击 / 拖动**阅读区：控制台不得出现 `Cannot hit test a render box with no size`（实机报过：`OverflowBox` 给子节点的约束无界，`Row` 没有尺寸却参与命中测试。现已改为 `Stack` + `Positioned`，每页都有确定宽高） |

## 4. R4 — 顶栏自身的交互

| # | 通过判据 |
|---|---|
| 4.1 | 展开缩放面板后再点旋转 → 缩放面板收起，**两块不叠** |
| 4.2 | 再点同一颗 → 面板收起 |
| 4.3 | 主行那颗缩放按钮的**图标随档位变**（适应窗口 / 适应宽度 / 原始大小…各不同） |

| 4.5 | 输入 `5000` 这类越界值 → 被夹到 1000%，不崩不空 |
| 4.6 | 拖动滑条过程中**不卡**（松手才提交）；松手后数值与滑条位置一致 |
| 4.7 | 「重置视图」只清缩放/旋转/宽页策略：**不动**单双页、阅读方向、页号 |
| 4.8 | 窗口宽度 < 900：五颗占位按钮不出现，主行**不溢出黄条**，书名仍可读 |
| 4.9 | 点占位按钮 → 弹一句「还没接进本仓的阅读器」，不是静默无反应 |
| 4.10 | 顶栏「钉住」与「点中间收起」「边缘悬停唤出」三条老路径都不被面板展开状态卡住 |

本轮的分界照 neoview：`fitMode` / `autoRotation` / `宽页策略` 落盘；`manualScale` / `rotation` 只在本次会话。

| # | 通过判据 |
|---|---|

| 5.2 | 放大到 300% → 换一本书 → **回到 100%**（跨书不该带倍率） |

## 7. R7 — 控制台洁净度（只看 log，不需要眼睛）

这一组不需要判断观感，跑的时候把控制台留着就行。

| # | 通过判据 |
|---|---|
| 7.1 | 打开一本书 → 翻 10 页 → 控制台**不出现** `setState() or markNeedsBuild() called during build`。实机测过：进书那一刻会刷 **14 条**（11 个 `ListenableBuilder` + 3 个工作区信息卡），根因是 `comic_read.dart` 在 build 阶段调 `ReaderSessionCoordinator.attachSession`，而那个中枢直接 `notifyListeners()` 打到正在 build 的下游。现已把**通知**推到本帧之后（状态本身仍同步写，同一帧里有代码直接读 `comicId` / `docs` / `displayTitle`）。<br>**这条目前只做到「按堆栈定位到根因 + 改完编译通过」，还没在真机复验**：复现两次都没能自动进阅读器，所以 0 错误不算证据 |
| 7.2 | 同一次操作不出现 `A RenderFlex overflowed`（对应 R3 的条纹） |
| 7.3 | 同一次操作不出现 `Cannot hit test a render box with no size`（对应 3.7） |
| 7.4 | 允许出现、且与本轮无关的：`AnyhowException(fetch failed: builder error)`（在线图源取图失败）、插件列表 CDN 回源失败 —— 都是网络，不是框架 |

## 8. 判定口径

- **R1 与 R2 有任何一条不过 = 本轮不通过**，其余组先别看（R1/R2 是回归，不是新功能）。
- R3 全过才算「上一轮报的黑黄条修好了」。
- 自动化已经覆盖的部分**不必人工跑**：缩放/旋转/宽页策略的数学有 40 条纯 Dart 断言
  （含「默认 `fit` 与改造前 `BoxFit.contain` 逐像素等价」），绑定解析有 Rust 断言。
  本文件只留**需要眼睛和耳朵**的部分。
