# 顶栏缩放 / 旋转（neo N-11）实机验收判据

> 范围与**刻意不做**的清单在 [feature-migration-spec.md](feature-migration-spec.md) 的 N-10 / N-11 / N-12 三行，
> 以及提交信息里；本文件**不重复写范围**，只回答一件事 —— **怎么判定一条真的通了**。
> 判据的作用与 [file-manager-acceptance.md](file-manager-acceptance.md) 相同：砍掉「看起来做了」的机会。

冻结信息：2026-09-20，对着**工作区**跑（这棵树同时有别的会话在未提交的改动里）。

**报告格式**：不通过时给 **条目号 + 控制台片段**，不要给描述。
症状到方法的映射必须是一对一的，否则修的人得先猜。

## 0. 入库红线：这三件事不算完成

1. **构建通过 ≠ 观感对。** 本轮改动全在渲染层，`flutter analyze` 与编译都证明不了任何一条视觉结论。
2. **面板画出来了 ≠ 它改的东西生效。** 每一档都要看到**画面**跟着变，不是看到按钮亮了。
3. **默认档变了观感 = 直接不通过。** 本轮唯一被允许改变默认观感的入口是顶栏面板本身。

## 1. R1 — 阅读位置（最高风险，先跑这组）

呈现层与配对是两件事：换缩放/旋转/宽页策略只该换「怎么铺」，不该换「看的是哪张」。
本仓已有明文纪律（`_syncPairingLayoutChange` 与 `remapReadModeSlotIndexForPairingChange`），
本轮把渲染层整个重写了一遍，所以这条纪律要重新验一遍而不是假定还在。

观察点：停在第 10 页附近，然后逐条操作，每次操作后**读左下角页号**。

| # | 通过判据 |
|---|---|
| 1.1 | 切 7 种缩放模式中的任何一种 → 页号不变 |
| 1.2 | 拖手动缩放滑条并松手 → 页号不变 |
| 1.3 | 顺时针 / 逆时针旋转 → 页号不变 |
| 1.4 | 切宽页策略三档 → 页号不变 |
| 1.5 | 「重置视图」→ 页号不变 |
| 1.6 | 自动旋转四组（关闭 / 纵向页 / 横屏 / 强制）逐个点 → 页号不变 |
| 1.7 | 单页 ⇄ 双页 → 停在**同一张图**（既有回归项，确认没被本轮改坏） |
| 1.8 | 「首页独立显示」来回切 → 停在**同一张图** |
| 1.9 | 「自动分割横向页」来回切 → 停在**同一张图** |

## 3. R3 — 溢出必须被裁掉，而不是被报警

上一版的缺陷：裁切用了 `UnconstrainedBox`，它带溢出指示 mixin，于是「帧比视口高」被画成
「BOTTOM OVERFLOWED BY 78 PIXELS」的条纹。现在换成 `OverflowBox` + `ClipRect`。

| # | 通过判据 |
|---|---|
| 3.1 | 适应宽度 + 一张超高竖页：纵向超出部分**被裁掉**，无条纹，图不缩小 |
| 3.2 | 手动缩放到 800%：无条纹；此时双指平移 / 双击放大仍能把裁掉的部分拖出来看 |
| 3.3 | 原始大小：无条纹（图比屏幕大时按视口裁） |
| 3.4 | 双页 + 高度对齐 + 放大：无条纹 |
| 3.5 | 旋转 90° 的横页：无条纹，且左右两侧是对称裁切而不是单边 |
| 3.6 | 上面任何一条做完后**收起顶栏**：阅读区不残留任何条纹 |
| 3.7 | 溢出状态下**点击 / 双击 / 拖动**阅读区：控制台不得出现 `Cannot hit test a render box with no size`（实机报过：`OverflowBox` 给子节点的约束无界，`Row` 没有尺寸却参与命中测试。现已改为 `Stack` + `Positioned`，每页都有确定宽高） |

## 7. R7 — 控制台洁净度（只看 log，不需要眼睛）

这一组不需要判断观感，跑的时候把控制台留着就行。

| # | 通过判据 |
|---|---|
| 7.1 | 打开一本书 → 翻 10 页 → 控制台**不出现** `setState() or markNeedsBuild() called during build`。实机测过：进书那一刻会刷 **14 条**（11 个 `ListenableBuilder` + 3 个工作区信息卡），根因是 `comic_read.dart` 在 build 阶段调 `ReaderSessionCoordinator.attachSession`，而那个中枢直接 `notifyListeners()` 打到正在 build 的下游。现已把**通知**推到本帧之后（状态本身仍同步写，同一帧里有代码直接读 `comicId` / `docs` / `displayTitle`）。<br>**这条目前只做到「按堆栈定位到根因 + 改完编译通过」，还没在真机复验**：复现两次都没能自动进阅读器，所以 0 错误不算证据 |
| 7.2 | 同一次操作不出现 `A RenderFlex overflowed`（对应 R3 的条纹） |
| 7.3 | 同一次操作不出现 `Cannot hit test a render box with no size`（对应 3.7） |

## 8. R8 — 顶栏排布与分组（本轮：图标不再堆在一起）

本轮改的全是**观感与可达性**，功能一颗没加、没减：主行按「导航 ｜ 标题 ｜ 视图 ｜ 版式 ｜ 增强 ｜ 窗口」
分组，组间一条竖线；所有图标按钮统一成 40×40；宽度不够就**整组让位**给末尾那颗「更多」，
而不是把图标挤小。自动化已经覆盖的部分见文末，这里只留需要眼睛的判据。

| # | 通过判据 |
|---|---|
| 8.1 | 宽窗（≥1060）主行：组与组之间**各只有一条**竖线，且**所有控件是同一个 40 的高度带**（图标钮、带字的芯片、条漫胶囊都齐平，不再有三种高度） |
| 8.2 | 主行上**看不到**那五颗 neo 占位（页面排序 / 全景 / 悬停滚动 / 幻灯片 / 放大镜）；打开末尾「更多」，它们在最后一节，点一下仍然出「XX 还没接进本仓的阅读器」 |
| 8.3 | 中档（880~1059）：「单页/双页」「方向」两颗芯片收成纯图标，**钉住与全屏**进「更多」，书名仍然读得出来 |
| 8.4 | 窄档（<880，手机上就是整屏宽）：主行只剩 返回 / 书名 / 循环模式钮 / **超分芯片** / 设置 / 更多 —— 超分那颗的显示与开关**必须留在第一行**（用户口径：它最常用），收进菜单就算不过。这一档让出去的是 视图三项、下载、**滚屏**、钉住、全屏 |
| 8.5 | 选中态从「主色实心圆」改成了 `secondaryContainer` 淡底 + 深色图标：确认「展开中的面板」「钉住开着」「双页开着」三种状态**仍然一眼能分辨**，且不再跟画面抢注意力。这是本轮最大的观感变化 |
| 8.6 | 桌面端鼠标悬停在任一颗图标上都有 MD3 的 hover 淡层（改造前手写的那几颗没有状态层）；按下有水波纹 |
| 8.7 | 手机上拇指连点 20 次图标钮：点不中或误触相邻颗 = 这条不过。本轮把 48 的可点区收成 40，这是**已知代价**，需要眼睛判它能不能接受 |
| 8.8 | 下载进行中的那一圈进度环看得见（它画在按钮底下，别被图标本身盖死） |
| 8.9 | 浅色主题下逐组看一眼：未选中的芯片是「透明底 + 一条 outline」，不许出现灰字配浅底读不清 |
| 8.10 | 「更多」菜单在**玻璃材质**与**透明蒙层**两种顶栏下都完整可见（菜单是独立 overlay，不该被顶栏的圆角裁到） |
| 8.11 | **在线图源**（插件漫画，不是本地文件夹）也要在第一行看到超分那颗：它没有逐页状态，画的是「总闸开着没有」+ 开关（`ReaderOnlineUpscaleChip`）。改造前它整块不画，就是用户报的「超分显示没了」。本地 GPU 漫画仍然走逐页那颗 |
| 8.12 | 在线图源上把超分开关**打开**：模型没下载时先弹一句「是否立即下载」，取消就什么都不改；下载完成才真的开（与本地那条路同一套问答，不能两种入口两种行为） |
| 8.13 | 窄档（<880）打开「更多」：里面要能看到 缩放/旋转/版式三项、下载、**开启自动滚屏**、钉住、全屏。让出去的每一项都得在，缺一项就是可达性断了 |

**自动化已覆盖，不必人工跑**：`test/comic_read/reader_top_bar_layout_test.dart` 共 32 条 ——

- 十档宽度（扫描点从阈值推出来，改常量会跟着挪）各两遍（收起与展开面板）断言**零溢出**；
- 主行**每一颗**控件（图标钮 / 带字芯片 / 胶囊容器）都必须是 40 高且中心线一致（混回三种高度就红）；
- 在线图源也画超分那颗（`ReaderOnlineUpscaleChip`）—— 曾经整块不画就是「超分显示没了」；
- 三档让位顺序：宽 = 全在 + 芯片带字，中 = 钉住/全屏进菜单，窄 = 视图三项、下载、**滚屏**也进菜单，
  而**超分始终留在第一行**；
- 「书名不被挤没」的宽度预算（阈值那一档书名 ≥240px）—— 上一版阈值 720 就是被它抓出来的
  （第一版阈值 720 时书名只剩 97px，第二版 960 时只剩 150px，都比窄档还窄）；
- **窗口拖动跨档**：同一棵树从 700 拖到 1000、从 1280 拖到 600 不许抛异常。
  这一条抓到一个真缺陷：芯片的 `AnimatedContainer` 原先在「见方 40」与「按文字撑开」之间
  插值约束，越线那一下会抛 `Cannot interpolate between finite and unbounded constraints`
  并让顶栏整条停止布局 —— 桌面端拖窗口必撞，编译与单档 pump 都发现不了。

## 9. 判定口径

- **R1 与 R2 有任何一条不过 = 本轮不通过**，其余组先别看（R1/R2 是回归，不是新功能）。
- R3 全过才算「上一轮报的黑黄条修好了」。
- R8 的 8.4 与 8.5 是本轮的两条主判据：前者是用户点名的口径（超分留在第一行），
  后者是本轮唯一「把强调色换淡」的地方，只有眼睛能判它有没有把状态读丢。
- 自动化已经覆盖的部分**不必人工跑**：缩放/旋转/宽页策略的数学有 40 条纯 Dart 断言
  （含「默认 `fit` 与改造前 `BoxFit.contain` 逐像素等价」），绑定解析有 Rust 断言。
  本文件只留**需要眼睛和耳朵**的部分。
