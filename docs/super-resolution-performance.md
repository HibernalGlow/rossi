# Apple 超分与预处理验证

阅读器的超分引擎可在 Breeze 原生 CoreML 与 mImage ONNX 之间切换，各自保留模型选择，缓存键包含引擎、模型、倍率和 ONNX 文件版本。

## 调度

参考 `vendor/mimageviewer/src/app.rs` 的相邻页交错预处理：当前页、下一页、上一页、下两页……。默认后续 2 页、之前 1 页，设置范围分别为 0～5，均为 0 时关闭预超分。

一个阅读器同一时间只执行一页推理。翻页替换尚未执行的任务；已进入原生推理的任务会先完成，暂不支持按 tile 抢占。背景页仅落盘，翻到该页才注入呈现器，避免后台结果切走当前画面。缓存复用不计入推理重试次数。

成功以呈现器 `usedEnhanced=true` 为准。文件生成、预超分完成和替换上屏分别记录。超分日志、复制日志、打开产物目录都可从超分设置使用。

## CoreML 模型

| 模型 | 原生倍率 | 输入和拼接 |
| --- | --- | --- |
| Breeze Real-CUGAN | 2× | FP32，192 输入，18 像素上下文，模型已裁边 |
| Real-ESRGAN x4plus | 4× | FP16，256 输入，16 像素上下文，输出裁边 64 像素 |

Real-ESRGAN 使用 [VincentGOURBIN/RealESRGAN-CoreML](https://huggingface.co/VincentGOURBIN/RealESRGAN-CoreML) 的社区转换模型，模型卡标明目标为 macOS 15+；本次仅在 macOS 验证。模型在设备上由 Apple CoreML 执行；实际 CPU、GPU、ANE 分配由 CoreML 决定。

[Real-ESRGAN 官方](https://github.com/xinntao/Real-ESRGAN) 存在专门的 `RealESRGAN_x2plus.pth`，本次尚未核实可直接安装的原生 2× CoreML 包。当前选项中的 x4plus 始终输出 4×。

## 性能实现

- CoreML 模型在内存中复用；输入双缓冲，预测最多领先拼接两块。
- 归一化采用 256 项查表，去掉多个整图浮点临时数组；预先计算反射坐标。
- 顺序拼接到 RGBA，复用行缓冲；避免多任务同时修改 Swift Array。
- 支持 FP16 / FP32 模型输入输出，按模型契约裁边；预测失败不会把输入当作输出。
- ONNX 复用输入存储和模型会话，按行融合，记录加载、准备、推理、融合和 PNG 编码耗时。日志中的 CoreML+CPU 表示允许 CPU 回退，不能据此断言所有算子使用 ANE。

## 2026-09-19 验证记录

使用两张真实照片的 1920×1080 副本，覆盖发丝、衣物、树叶和木纹。没有使用色块作为性能或画质依据。原图文件未修改。

- CUGAN：实际输出 3840×2160；输入／拼接优化后与原实现的输出逐像素一致。
- 阅读器日志确认 CUGAN 背景页完成后，翻回该页直接复用并上屏，未再次推理。
- 原生 ESRGAN：实际输出 7680×4320；最终实现两次完整推理为 36.4 秒和 65.9 秒，仍属于重模型。
- 原 ONNX x4plus 路径在超过 8 分钟尚未产出时停止基准；采样观察到 ORT CPU Concat / Conv / LeakyRelu。该结果不代表所有 ONNX 模型都如此。
- CUGAN 相邻对照的热运行：原实现 2.14 / 2.18 秒，新实现 2.16 / 2.53 秒；另一次新实现为 1.76 秒。尚未证实稳定的吞吐提升，收益主要是减少临时分配和预超分命中后的复用。
- 测试机器同时运行其他编译任务并大量使用交换内存；单次时间波动显著，不能把不同时段的耗时比直接当成稳定加速比例。
