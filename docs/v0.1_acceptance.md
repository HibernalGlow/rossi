# v0.1 验收判据

> 这是 v0.1 的**唯一判据**。它不是 ADR（可随数据调整），权威性来自 `docs/ROADMAP.md` 的引用。
> 判据的作用是**砍掉「顺手再加个功能」的机会**，不是性能 KPI。

范围前提见 ADR-0008（v0.1 = 本地漫画 → 归档直读 → 解码 → GPU 上屏 → 超分）
与 ADR-0009（v0.1 另含操作绑定体系，见判据 E）。

## 1. 判据

### 判据 A — 覆盖度

三种本地来源**都能读到最后一页**，页序正确，进度可续读：

| 来源 | 现状 |
|---|---|
| `CBZ` | 依赖已在（`windcore` 已依赖 `zip 8.2.0`） |
| **`CBR`** | **需要新依赖**（`windcore` 里没有任何 RAR 支持；随 mImageViewer 的 `unrar-patched` 检出一起引入，读取模型见 §4.3） |
| 散图文件夹 | 纯文件系统枚举，无新依赖 |

> 「CBR」读作**非固实、未加密的 CBR**——solid / 加密不在本判据内（ADR-0011，见 §4.3）。

### 判据 B — 冷启动到第一页 ≤ 2 s

- 定义：从进程启动到**第一页完成光栅化并可见**（不是「窗口出现」）。
- 取**连续 3 次启动的中位数**——首次启动要读 DLL，单测一次会把盘读算进去。
- 平台：Windows / Release 构建 / 页尺寸 3840×2160。

### 判据 C — 翻页无可感知卡顿

自动连续翻页 **100 次**（不手动，避免人为节奏干扰），以 `FrameTiming` 的
`buildDuration + rasterDuration` 为帧时间：

| 指标 | 阈值 | 为什么是这个数 |
|---|---|---|
| `p95` 帧时间 | **≤ 16.7 ms** | 60 Hz 的一帧预算；绝大多数帧必须不超预算 |
| `p99` 帧时间 | **≤ 33 ms** | 最差的 1% 仍不超过两个 vsync，即「最差也只漏一帧」 |
| 单帧上限 | **不允许任何 > 100 ms** | 这是「卡住」而不是「不跟手」，肉眼确定可见 |

**不采用平均 FPS 作为判据**：平均 60 fps 完全可以掩盖一次 200 ms 的停顿，
而停顿正是翻页体验里唯一真正被感知的东西。

### 判据 D — 连读三本内存不增长

连读三本（每本 ≥ 100 页，**其中一本必须是 CBR（非固实、未加密，见 §4.3）**）：

- 基线 = **第 1 本读完后**的驻留量（不是峰值）；终点 = 第 3 本读完后。
- `RSS` 增幅 **≤ 5%**。
- **纹理 / handle / 延迟释放队列计数必须回落到基线附近，不允许单调上升。**

> 最后一条是 Gate A 的直接教训：**GPU 侧（显存）泄漏不体现在工作集里**，
> 只看 RSS 会漏掉它，必须读探针计数。

### 判据 E — 操作绑定可改、可存、可迁移

依据 ADR-0009。v0.1 的运行时只覆盖 **5 类 descriptor**（`keyboard` / `mouse` / `wheel` /
`touch` / `area`），但 schema 一次覆盖 9 类。五条子判据：

| # | 子判据 | 口径 |
|---|---|---|
| E1 | **动作 id 是稳定契约** | 每个可绑定动作有唯一 id；绑定项只引用 id，不引用私有方法名 |
| E2 | **默认绑定非硬编码** | 改绑定（不重新编译、只改配置）后行为随之改变；`key.dart` / `reader_input_controller.dart` 里不再留键位判断 |
| E3 | **冲突阻止保存** | 同 `context` + 同输入键 → **拒绝保存**并指出冲突双方；不能只警告 |
| E4 | **导出 / 导入往返一致** | 导出 JSON（带 `format` + `format_version`）→ 导入 → 绑定集合完全相等；版本更高的包**不崩**（保留或安全忽略未知字段） |
| E5 | **翻页走真实路径** | 判据 C 的自动翻页 100 次**经绑定引擎派发「下一页」动作**，不是直接调 controller 方法 |

E1–E4 用 `flutter test` 覆盖（纯 Dart，不需要 GPU、不需要 Release）；
E5 与判据 C 同一次测量，不另跑一遍——否则测的还是「模拟按键 + 渲染」。

**明确不算判据**：手柄运行时、轮盘菜单、鼠标轨迹手势、动作序列（`followUpActions`）、
多套 profile。它们只要求在 schema 里**可解析**（预留位），不进运行时与设置 UI。

> 追溯：判据 E 由 ADR-0009 引入，2026-09-16 正式写进本文件。
> 在此之前 `ROADMAP.md` 与本文 §范围前提都引用了「判据 E」而 §1 未定义，
> §5 却写「五条全部满足」——是本文件与 ADR-0009 的落地不同步，现补齐。

## 2. 测量口径（不满足这些前提的数字一律不算）

1. **Release 构建**。Gate A 的全部数据都是 Debug，判据只在 Release 下成立。
2. **同一台基准机**（当前：RTX 4060 Laptop / Windows）。换机器要重采基线。
3. **真实内容**：漫画扫描件/照片页，不是纯色或低熵测试图。（Gate A 带宽测试就吃过这个亏：
   全零数据被显存压缩，读数虚高 40%。）
4. **不带调试器、不接 profiler** 跑判据；诊断可以另跑。

## 3. 明确不算判据

- 超分画质、超分速度（Gate B 管）
- 在线源、上色（仍在 ADR-0008 冻结线外）；**视频页与 OCR 翻译成品页已分别按 ADR-0016 / ADR-0018 解冻，
  但不进入 v0.1 判据** —— ADR-0018 明确「判据 A–E 不变」，它只新增一条约束：
  **开 OCR 后翻页帧时间不得劣化**（渲染路径只读成品页缓存）。
- UI 精致度「像不像 neoview」
- **macOS 行为**（Gate A-M 另算，本机无机器）

## 4. 实现判据 A 需要付的成本（已查证）

### 4.1 CBR 是三条里唯一要新依赖的

`windcore`（`rust/Cargo.toml`）现有的归档相关依赖是 **`zip 8.2.0`（deflate/time）、
`sevenz-rust 0.6.1`、`tokio-tar`、`flate2`、`zstd`、`brotli`** —— **没有任何 RAR 支持**。
mImageViewer 的做法是 `unrar 0.5.8`（path 指向它自己打过补丁的 `crates/unrar-patched`，
补的是 `UCM_CHANGEVOLUMEW` 回调固定 2048 字符读取越界，与许可证无关）。

→ Rossi **沿用这份检出**（`vendor/mimageviewer/crates/unrar-patched`），不另找 crate。
那条补丁在**分卷 CBR** 上会真的命中：`RAR_VOL_NOTIFY` 的 `P1` 可能指向按当前名字长度分配的
`std::wstring`，定长切片会跨过分配边界（ADR-0011 §6）。

### 4.2 UnRAR 许可证：不撞「不引入 GPL」，但要记账

已核对 UnRAR 官方许可证原文：源码**可用于任何软件处理 RAR 归档，免费、无限制**，
**不是 copyleft**（不要求衍生作品同许可证）。两条义务：

1. **不得**用于开发 RAR 兼容压缩器或重建 RAR 压缩算法（我们是只读，不受影响）；
2. 分发时**必须附上该段许可证文本**（随包文档或源码注释里）。

→ 它**不违反** ADR-0008 的「任何 GPL 源码不得进仓」，但属于**需要显式记账**的第三方条款。

### 4.3 RAR 的读取模型：按需读条目，禁止整章落盘

**先纠正一条被写宽了的约束。** 它原先是「RAR 读不了流」——正确的边界是：
以**文件路径**为前提的是**归档本身**（`unrar` / `sevenz` / `delharc` 都如此），**不是条目字节**。
条目字节可以进内存：mImageViewer 的 `src/rar_loader.rs::read_entry_bytes` 就是
`open_for_processing()` → 循环 `read_header()` → 命中 `header.read()` 返回 `Vec<u8>`、
未命中 `header.skip()`；函数返回即释放句柄，不跨调用持有任何归档对象。

**被否决的实现**（来自 `comicrd_core`）：首次访问 chapter 时把整章图片一次性提取到
`<app-data>/rar-sessions/chapter-<id>`，之后 probe / read 走磁盘，配 LRU（上限 2）与三处清理。
它把「打开一本 CBR」变成一次全量解压加一份等量磁盘副本——200 页就是 200 张图落盘。

**Rossi 的约束（ADR-0011）**：

- 不落盘、不建 session、不跨调用持有归档句柄；
- 条目字节直接进内存交给解码器；
- 缓存**只允许缓存判定结果**（key = `path + len + mtime`），不允许缓存归档内容或句柄。

**唯一允许临时文件的场景是嵌套归档**（内层必须先落地成路径才能被打开），v0.1 不实现嵌套。

**不在判据内**：solid / 加密 CBR。实现按 mImageViewer 的 `classify_direct_read` 给出
`Direct` / `Solid` / `NestedArchive` / `Encrypted` 判定，遇到后两者报明确错误即可。

**未测项**：非固实归档下 `skip()` 的实际开销（libunrar 是走 seek 还是走解压）。
列入 Phase 0 实测，两个数都记：顺序读第 200 页 vs 整章落盘。

### 4.4 vendor mImageViewer 之后会出现的依赖双份

| 功能 | rossi 现在 | mImageViewer |
|---|---|---|
| ZIP | `zip 8.2.0` | `zip 2` |
| 7z | `sevenz-rust 0.6.1` | `sevenz-rust2 0.20` |
| RAR | 无 | `unrar 0.5.8`（本地补丁版） |

Cargo 允许同一 crate 的多个大版本共存，但**会编译两份**，且 API 分裂。
这正是 ADR-0001 里「cargo 的粒度是 crate」那条代价的具体形态 —— 不是理论风险。

## 5. 判定

五条**全部满足**才算 v0.1 达标。任何一条不满足 = 不进入「日常使用」阶段，
也不开始 macOS / Linux 外推（ADR-0006）。

不满足时**先改实现，不先改判据**；确实要改判据，须在本文件里写下改的原因与新数据。
