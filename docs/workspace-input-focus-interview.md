# 泳道输入与视觉聚焦访谈

日期：2026-10-11。状态：用户已确认，决策见 ADR-0022，进入实现。

## 目标与已知约束

用户希望消除泳道切换时的等待感，同时兼容操作绑定的上下文识别、键盘与鼠标操作、轮盘菜单、泳道自动定位，以及从屏幕边缘拉回完整显示的行为。

按用户要求：先通过 grill-with-docs 访谈敲定细节，再形成 ADR，随后实现和验证。
现有词汇见根目录 CONTEXT.md；已有交互决策见 ADR-0014。新决策应明确替代哪些旧规则。

## 第一轮：键盘操作的默认归属

场景：没有输入框或弹层，刚在 Reader 阅读，鼠标移到左侧书架，尚未点击或等待自动回拉，立即按方向键或轮盘快捷键。
待答：这次操作应当作用于哪条泳道？
建议：鼠标所在泳道立即成为此次操作的目标，输入不等待视觉定位完成；文本输入、轮盘打开和拖拽期间的规则留待后续确认。
用户回答：默认根据鼠标所在泳道确定操作上下文，支持按泳道自定义，后续使用后可以自行调整。自定义的具体范围尚待确认。

已核查现有操作绑定、Reader 输入宿主、泳道吸收层与菜单的真实事件路径，避免重复建设输入引擎。此处只记录证据，不以实现现状替代产品决策。

## 第二轮：集中确认当前决策

用户要求一次集中询问相关细节，减少逐题往返。以下条目已由用户集中确认，Q2/Q3 补充以最新回复为准。

- Q2 自定义的范围：区分每泳道的焦点行为偏好与已有操作绑定。建议按泳道自定义上下文跟随方式和自动定位行为，沿用现有绑定系统。
- Q3 指针落在空白、顶栏或窗口外时的键盘目标：建议保留最近一次有效目标；纯键盘切换也可改变该目标，窗口失焦暂停分发。
- Q4 非激活泳道首次点击：建议第一下按实际点击对象执行，同时确认泳道；明确覆盖 ADR-0014 的首次点击吸收规则，需用户决定。
- Q5 非激活泳道首次滚轮：建议第一下就作用于指针命中的内容，消费一次；连续滚动期间保持起始目标，避免布局移动劫持剩余滚动。
- Q6 自动定位：建议保留停留后自动回拉完整显示，输入路由立即生效，经过泳道不触发布局移动；Reader 独占及自动独占偏好继续兼容。
- Q7 动画中的交互：建议点击/拖拽期间暂停自动回拉，手势结束后再定位；新定位请求从当前位置取代旧请求。键盘和滚轮不等待动画。
- Q8 边缘揭示与恢复：建议保留已有揭示时是否激活的设置；进入后输入立即可用，开始明确操作后结束临时揭示，不再自动收回；只看一眼则按原恢复规则回去。
- Q9 输入框、输入法组合、弹层、轮盘、拖拽：建议这些交互保留原始目标直至结束，菜单打开后不随指针跨泳道变化；结束后恢复通常规则。
- Q10 交付范围与设置：建议先优化有鼠标的泳道模式，保持触屏原有入口；按泳道设置需要持久化并复用现有配置/同步边界。验收以首个输入不丢、动作不串泳道、完整回拉、不引发 Reader 画面重排为准。

用户回答：Q2 要复用已有操作绑定系统和上下文，泳道自定义仅负责选择目标及定位习惯；Q3 接受保留最近有效目标，同时要求输入框/打字不能误触发阅读器动作。Q4/Q5 明确第一下必须执行，不能要求二次点击或先激活再滚动。其余按推荐。

## 最终核查与落定

现有绑定引擎已支持 reader/video/panel/editor/modal 上下文；工作台仅按 activeLaneId 报告 reader/panel，文本保护仅在上层转发入口。阅读器自身入口与长按定时器需要统一保护。非激活内容的 AbsorbPointer 同时挡住点击与滚轮，应移除。

泳道输入目标负责即时选择归属，视觉激活继续负责停留后最小滚动和独占偏好；上下文解析及优先级沿用既有系统。编辑、弹层、轮盘及拖拽拥有交互，不被鼠标经过抢走。动画会替代旧活动，没有串行队列；应合并下一帧定位请求并在手势期间停止自动滚动。

详见 [ADR-0022](adr/0022-workspace-lane-input-target.md)。

后续界面调整：用户要求不重复展示三份相同设置，改为一个“泳道交互”区，通过 Tab 切换泳道，分别保存各自偏好。

后续手感调整：用户反馈悬停完整显示的滚动仍不够连贯。定位运动改为临界阻尼，同一落点不重复起步，换落点承接当前速度，直接手势依然中断定位。
