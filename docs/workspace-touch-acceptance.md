# 泳道工作台的触屏触发的实机验收清单

对应改动：`WorkspacePointerMode` / `hasHoverPointer`（新）、Reader 独占时的 44px 切换轨、
`hasWorkspaceEntry` 与 `workspaceAvailableOnDevice` 分家、「设置 → 布局」顶部的
「进入工作台」、面板栏把手的长按。口径与代价见
`docs/adr/0012-workspace-swimlane-reader-lane.md` 的第 14 条。

**已经自动验到的（不必手测）**：`flutter test test/workspace/swimlane_runtime_test.dart`
（15 条，含新增两条：触屏 ⇒ 左右收成轨 + 点轨真的交出交互；桌面 ⇒ 同一份设置不给轨）、
`test/workspace/workspace_startup_test.dart`（手机「没有那颗按钮但可用」+ 六档平台穷举）、
`test/workspace/top_chrome_test.dart`（顶栏形态改为委派给新判据之后照旧全过）。

下面这些是**只有眼睛能判**的：手指够不够得着、按下去对不对、以及在 369dp 宽的手机上
这套横条带到底读不读得下去。测试机：24129PN74C，Android 17，`arm64-v8a`，
1200×2670 / 520dpi ⇒ 竖屏 369dp、横屏 821dp。

## A. 进得去 / 出得来

- [ ] **T1 入口在不在**：设置 → 全局 → 「布局」这一项**在手机上出现**了
      （改动前它被「本机没有工作台入口」挡掉）。
      失败长这样：设置里根本没有这一项 —— 那就是 `workspaceAvailableOnDevice` 没生效。
- [ ] **T2 进去**：进「设置 → 布局」，最顶部那颗「进入工作台」按下去，
      **真的换到了工作台这一整页**（按上面选的呈现：泳道或四边栏）。
      失败长这样：按一下没反应，或者进去是空白。
- [ ] **T3 出得来（三条各试一次，别只试一条）**：① 系统返回键；
      ② 泳道栏头「更多」菜单里的「退出工作台」；③ 外接键盘的 `Esc`。
      每一条都要**回到导航栏**而不是退回桌面/杀掉进程。
- [ ] **T4 开屏页那一项**：设置 → 行为 → 开屏页，下拉里能看到并选中「工作台」；
      杀进程重开 ⇒ 直接落在工作台；把导航栏的返回键按到底 ⇒ 能出去。

## B. 左右泳道的触发（本轮的正题）

- [ ] **T5 轨在不在**：进入泳道模式、开一本漫画，按栏头的「独占该栏」让 Reader 独占。
      此时视口**最左与最右各有一条 44px 的窄轨**（不需要事先去设置里开
      「Reader 独占时显示泳道切换栏」—— 那颗开关在触屏上被绕过了）。
      失败长这样：左右干干净净什么也没有 ⇒ 那两条泳道在触屏上不可达，正是要修的那个洞。
- [ ] **T6 点轨交出交互**：点左轨 ⇒ 左泳道被推出来**并成为激活泳道**（栏头边框高亮、
      里面的卡片第二下就能点）；点右轨同理。
      失败长这样：点了没动，或者动了但第一次点卡片仍无反应（= 激活没发生，
      只有条带被移动了）。
- [ ] **T7 回 Reader**：从轨进入左/右泳道之后，Reader 应当仍然露出**一条窄缝**
      （默认 56px）。点那条缝 ⇒ 回到 Reader 独占。
      失败长这样：Reader 整条被挤出视口，只能靠另一侧的轨再呼出来。
- [ ] **T8 轨不该被误按**：正常阅读时手指在屏幕上翻页、拖动进度，**不应**出现
      「焦点自己跑到左/右泳道」。轨只有 44px，但它是唯一把手，
      所以这条是「值不值得存在」的判断，不是回归 —— 如果误按频繁，说一声，
      下一轮改的是轨的**位置/宽度**，不是把它撤掉。
- [ ] **T9 竖屏 vs 横屏**：竖屏（369dp）下这套横条带的可读性 ——
      **明说：本轮没为竖屏做版式**，默认档三条泳道装不下，靠条带滚动 + 轨。
      横屏（821dp）应当明显可用。请各看一眼，告诉我要不要把「手机上默认只给
      一条面板泳道」这类收窄做成默认。

## C. 长按补上的那个菜单

- [ ] **T10 面板栏把手长按**：泳道顶栏里那个「拖拽把手」图标（面板栏的把手），
      **长按**应弹出与桌面右键**同一个**菜单（改为悬浮 / 限制在本泳道 / 恢复默认位置）。
      失败长这样：长按变成拖动（菜单没出来），或者弹了但选项与右键不一致。
- [ ] **T11 拖动仍然可用**：按住同一个把手**移动** ⇒ 是把面板栏拖走/转悬浮，
      不是弹菜单。这一条和 T10 是一枚硬币的两面：两个手势共存在同一个识别器上，
      只验一个会假绿。
- [ ] **T12 唤出区那张卡的提示**：设置 → 布局 → 「悬停唤出区」，
      在手机上应明写「这几块要鼠标贴住边缘才生效，触屏请用 Reader 独占时两侧的窄轨」。
      这一条只是文案，但它挡住的是「改了半天画布毫无反应」这种白工。

## 明确不做的（别在这儿找）

- **不做「按住边缘不放把泳道呼出来」的触屏版边缘驻留**：它要和阅读器的翻页抢同一个
  手势 arena，而 T5 的轨已经解决可达性。
- **不给页签「收起面板」加触屏入口**：收起只有右键，恢复在页签条右侧「已收起」里
  （触屏可点），所以触屏用户不会陷进去。要补的落点是泳道「更多」菜单列一遍面板。
- **不改底部导航的信息架构**：手机上没有新增 tab，入口在设置里（理由见 ADR-0012 第 14 条第 3 点）。
